## 统一交互

所有页面顶部均有轻量「任务」入口与「外观」入口。任务数量代表活动任务，不是设备数。点击任务打开抽屉，逐条显示微信号、实际设备、操作及进度；同一时间只打开一个业务抽屉。点击任务中的异常，进入诊断并带入任务或筛选上下文。

消息台依次选择微信号与执行设备。只有一个可用候选时，设备选择器收敛为文字。自动选择显示当前计划设备，提交后任务记录中的设备为最终执行目标。手动指定不能静默切换。忙碌设备若支持队列可选择并提示排队；离线或账号不匹配时不可提交。

消息台图中下拉展示的是同一微信号的关联候选，部分可能来自历史关联；系统设置显示的是整个系统各设备的当前登录状态。两张图是独立演示状态，不是同一时刻的运行快照。设备切换账号后，实际界面必须即时更新关联和候选。

AI 图展示的是规划中的账号覆盖状态，模型可继承全局，角色可单独覆盖。规则列表第三方视觉生成的文字偏差以设计说明为准；实际字段不使用红色星号来表示名称通配符，通配符与名称使用相同文本颜色。

转发目标优先选择微信号和会话，只有展开高级设置才显示「自动选择 / 指定设备」。抽屉保存独立提交该规则，不增加整页保存。

系统设置首期不放未具备能力的批量选择框。后续支持批量重新识别时，再加入勾选列与选中后工具栏。正常状态只显示已保存，修改后才出现保存与放弃操作。

诊断图中筛选与列表只代表当前加载范围，不能声称全历史查询。结果未知需要核对原设备，不因为其他设备可用就自动重发。

图稿展示未来完整交互方向，设备别名、任务数量、手动选路、账号级 AI 继承等需要后端支持，不代表当前代码已经提供。分阶段实施及任务归属规则见 [多设备与多微信号设计补充](多设备与多微信号设计补充.md)。视觉、控件及保存原则见 [子页面设计说明](子页面设计说明.md)。
