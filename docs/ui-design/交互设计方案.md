# 微信消息台 UI 与交互设计方案

日期：2026-10-10 · 阶段：设计评审 · 本次不修改业务代码

## 1. 设计结论

采用「全局导航 + 页面工作区」结构。微信消息台是日常操作首页；系统设置、AI 设置、消息转发、诊断是独立页面。将原有的大型设置弹窗改为页面，仅保留账号选择浮层、设备详情抽屉和短表单弹窗。

左侧导航：品牌 / 微信消息台 / 分隔线 / 系统设置 / AI 设置 / 消息转发 / 诊断。四个管理入口严格按用户指定顺序排列。消息台需要常驻入口，避免进入设置后无法直观返回。

## 2. 现有体验与改进

| 现状（依据现有页面与脚本） | 改进 |
|---|---|
| 手机连接、全局 AI、转发均使用长弹窗 | 配置进入独立页面，长列表有足够空间，支持局部保存 |
| 账号下拉已有，但账号、连接地址分散在会话侧栏 | 顶部明确显示「当前微信号 + 执行设备 + 状态」 |
| 手机连接入口同时承担全部设备管理 | 当前设备抽屉用于快速查看；系统设置用于全部设备管理 |
| 诊断独立页面，视觉结构不同 | 使用同一导航与顶部栏，保留筛选和任务详情 |
| 暂无主题入口 | 全部页面右上角常驻「外观」按钮 |

设计图中的账号、设备、消息和统计均为演示数据。

## 3. 全局结构

- 导航展开宽度 208px，折叠宽度 64px；图标配文字，选中项用浅主题底色和左侧标记。
- 全局顶部栏高度 64px，左侧显示页面名称，右侧显示外观设置。账号切换属于消息台，不放在所有页面的全局栏中。
- 管理页面宽度随窗口变化，主要表单最大宽度约 1040px；分组标题、说明、字段与保存区清晰分离。
- 诊断红点只提示仍需处理的异常；不把历史失败总数永久挂在导航上。精确计数与已处理状态属于后续能力。
- 离开有未保存修改的页面时，提示「保存并离开 / 放弃修改 / 留在此页」。已保存的配置展示保存时间及生效范围。

## 4. 微信消息台

### 4.1 布局

页面顶部上下文条：微信号选择器 → 当前设备名称与文字状态 →「连接详情」。下方为会话列表（约 296px）与聊天区；设备抽屉按需覆盖右侧，不长期占据聊天空间。

会话列表：搜索联系人或群聊、新建会话；全部 / 联系人 / 群聊 / 未读；会话行显示名称、摘要、时间、未读数。搜索和列表仅针对当前微信号，空列表明确显示该账号名称。

聊天区：会话名称与群聊/联系人类型；读取最近消息、会话设置、更多（导出）；聊天正文；固定输入区。会话 AI 状态作为简短标签，点击进入会话设置。

### 4.2 微信号下拉与筛选

「打通」定义为已授权设备且成功识别微信号；在线与离线另设状态，避免把离线账号当作丢失。

选择器触发器显示昵称、微信号和在线状态。展开后提供搜索（昵称/微信号）、筛选「全部已接入 / 在线」，列表逐行显示昵称、完整微信号、关联设备、文字状态、选中勾选。默认全部已接入，在线账号优先；离线账号仍可查看历史。搜索无结果显示「没有匹配的微信号」，提供清除筛选。

首次进入：恢复上次选中账号；该账号已移除则选择首个在线账号，无在线则选择首个已接入账号。无账号展示「连接手机」引导。未识别和旧数据的「未归属账号」作为独立辅助入口，不混入在线筛选。

切换账号：立即更新设备、会话列表及操作目标；恢复该账号上次查看的会话，否则展示空态；草稿按账号与会话隔离保留。原账号已提交的任务继续执行，任务状态仍归属于原账号。不能将原聊天窗口直接套用新账号。

发送区域常显「由 工作号 · Pixel 8 发送」。离线时禁用发送与读取，可输入并保存草稿；提示「设备离线，可查看历史消息」，提供连接详情入口。消息不自动转交其他微信号。

### 4.3 消息状态

区分排队中、执行中、等待手机确认、发送成功、发送失败、结果未知。只有实际返回成功才显示成功；结果未知提示「请先在手机核对」，提供查看诊断，避免一键盲目重发。读取失败不清空现有聊天记录。正在翻看历史时新消息显示底部提示，不强行滚动。

## 5. 当前设备连接抽屉

点击顶部「连接详情」，右侧打开约 400px 抽屉，背景页面保持上下文。

| 分组 | 内容与行为 |
|---|---|
| 概况 | 设备名称、在线/离线/连接中/待授权/账号未识别、当前微信号 |
| 连接信息 | 连接方式（已授权加密连接 / 旧版手动连接）、设备编号、地址；复制按钮 |
| 健康状态 | 最近连接/同步时间（有数据才显示）、现有异常原因；不能用「在线」推断所有操作可用 |
| 快捷操作 | 重新识别微信号、查看该设备诊断、管理全部设备 |
| 手动连接设置 | 仅旧版连接允许编辑地址和 Token，Token 默认隐藏；留空保留原值 |
| 授权管理 | 撤销授权放在底部危险区域，确认后断开；明确历史记录仍保留 |

加密反向连接的地址是观测信息，不显示为可修改表单。设备别名、最近同步时间、连接测试及显式重连若缺少接口，列为后续扩展，不假设已经可用。

同一账号关联多个设备时显示实际执行设备和其他设备列表。第一版沿用现有「在线优先」选择逻辑，不承诺可手动指定执行设备；后续增加明确选路能力后再提供切换控件。

## 6. 四个管理页面

### 系统设置

页内分组：设备与连接（默认）/ 自动发现 / 消息读取。

设备表格列：设备、微信号、状态、连接方式、操作；顶部「搜索设备」「手动添加」。授权引导采用分步卡片：发现设备 → 输入手机验证码 → 手机允许 → 账号识别完成。网页验证成功和手机确认分别显示状态；显示验证码剩余时间及失败信息。

自动发现：自动搜索开关、本地网络开关、频率、跨网段列表、预算。保留现有每段最多 1024 地址、总计 4096、最多 8 段等约束，字段附近即时解释错误。手动添加归入兼容入口。

消息读取：保留读取最近历史消息设置；说明生效时机。监听地址等目前需要修改文件并重启的配置以只读说明呈现，不伪装成已可在线保存的字段。

### AI 设置

分组为模型连接、默认角色、名称回复规则。接口地址、模型、密钥、角色提示词、图片开关保持现有能力。密钥隐藏，留空保留含义明确。会话独立设置优先，其次首条匹配的名称规则；列表展示优先顺序、匹配方式、回复模式。拖动排序与连接测试为待补能力，可先用上下移动调整优先级。

页面顶部说明作用范围是全局规则，不随消息台账号切换。显示会话实际使用的规则及覆盖原因属于后续增强。群聊触发词必填、自动回复间隔等约束保持一致。

### 消息转发

规则表格显示启用状态、名称、来源账号/会话、目标账号/会话、条件；编辑用抽屉。来源和目标选择器均显示账号，不能只有同名群标题。来源与目标可以跨账号，每个目标必须有可用设备。

编辑顺序：来源 → 过滤条件 → 目标 → 摘要确认。保存前展示自然语言摘要。明确只转发保存后读到的来信，以及表情包、系统提示等现有限制。离线目标提供提示；循环规则检测、测试匹配、最近执行统计列为后续能力，未实现前不得标记校验通过。

### 诊断

统一导航，顶部筛选账号、设备、时间范围。概览 → 最近异常与降级 → 读写任务 → AI 任务 → 可折叠日志。异常优先展示人能理解的原因及下一步，技术详情折叠。任务详情显示账号、设备、操作、阶段与结果。

时间范围/账号筛选及跳转定位需要核对接口支持；第一版可对已加载数据筛选，但必须标注数据范围，避免声称搜索全部历史。结果未知的发送任务始终提醒先核对手机。

## 7. 右上角外观设置

点击「外观」打开小浮层，所有页面一致。

- 显示模式：浅色 / 深色 / 跟随系统；默认跟随系统。
- 主题色：微信绿（默认）、蓝、紫、橙；颜色圆点附文字名称及选中勾选。
- 选择即时预览并自动保存；偏好保存在当前浏览器，刷新、切换页面保留。
- 主题色作用于主按钮、选中导航、焦点及选中态；成功/警告/错误色保持语义，不随主题改变。暗色模式单独设置背景、边框和文字色。
- 不只靠颜色表达连接状态，文字对比度目标 4.5:1，图标按钮有名称与键盘焦点。

第一版不增加自由取色器或密度设置，避免偏好选项过多。

## 8. 空态、异常与响应式

| 场景 | 页面反馈 |
|---|---|
| 无设备 | 消息台引导连接，其他管理页面仍可访问 |
| 已授权但未识别账号 | 显示账号识别中/失败，提供重新识别 |
| 账号离线 | 历史保留、草稿可编辑、发送与读取禁用 |
| 在线但不可操作 | 显示可操作性异常原因，发送与读取按能力禁用 |
| 数据加载失败 | 内联重试，不把加载失败显示为无账号 |
| 保存失败 | 保留输入并就地展示错误，成功后再关闭抽屉 |
| 会话无消息 | 显示读取最近消息入口及当前账号 |

≥1280px 展开导航与双栏消息台；960–1279px 导航折叠；低于 960px 会话列表与聊天按页面切换，保留返回按钮，设备详情全宽展示。窄屏仍可切换微信号。Esc 关闭浮层和抽屉，关闭后焦点返回触发按钮；下拉支持键盘搜索与选择。

## 9. 实施范围与验收

第一阶段：统一导航和页面外壳，设置从弹窗迁至页面；账号搜索与在线筛选；当前设备抽屉；外观模式及预置主题色；离线和结果未知反馈。

第二阶段：设备别名、连接测试、显式重连、规则执行统计、规则循环检测、诊断历史筛选、人工选择执行设备。实施前确认后端数据及接口。

验收重点：四个管理入口顺序正确且可返回消息台；账号切换无串号、草稿不丢失；离线账号可查历史；当前连接信息与执行设备一致；新版连接地址不可误改；主题跨页面及刷新保留；失败保存保留表单；发送未知状态不会诱导重复发送。
