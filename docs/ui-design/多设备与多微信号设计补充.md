# 多设备与多微信号设计补充

2026-10-10 · 后续能力设计 · 不修改业务代码

本补充是后续多设备支持的设计基线。涉及设备选择、任务归属和配置范围时，以本文件为准；前面的图稿是单设备上下文示例，实施时按这里扩展。

## 1. 账号与设备分别管理

微信号拥有会话、历史消息、草稿和会话规则；设备拥有连接、授权、可操作状态和执行队列。设备不是微信号的永久别名，不能按 IP 地址关联聊天记录。

一个微信号可以在历史上关联多台设备；一台设备也可能先后登录不同微信号。当前可执行关联必须由设备实时识别和核对，不假设所有设备都支持同时登录多个微信号。

界面使用昵称方便识别，同时显示完整微信号；设备使用可编辑别名，同时保留稳定设备编号。地址作为连接信息，不能作为设备主标识。别名、实时绑定和手动选路需要后续服务端支持。

## 2. 消息台顶部：先微信号，再执行设备

顶部上下文条调整为：

**微信号：工作号 · wx_work_01 ▾　执行设备：自动选择 · Pixel 8 ▾　在线　连接详情**

微信号下拉支持搜索昵称/微信号，筛选「全部已接入 / 可用」；每行展示「2 台设备 · 1 台可用」等汇总，展开选择的是账号，不同时承担设备选择。可用表示存在能够执行当前账号任务的设备，不能仅依据网络在线。

执行设备选择器只列出当前微信号关联的设备，默认「自动选择」，并显示当前实际选中设备。只有一台可用设备时用静态文字代替下拉，减少无意义选择；有多个候选或需要查看离线候选时才显示选择器。

设备项显示别名、设备编号末尾、在线状态、是否可操作及占用情况。离线和不可操作设备可查看详情，但不能作为立即执行目标。

自动选择以账号匹配、可操作性和队列情况决定；具体调度规则需要后端确定。用户手动指定后，目标不可用时明确阻止操作，不能静默换设备。自动模式允许在任务提交前选择其他合格设备，并在提交结果中说明实际目标。

发送区保持只读提示「由 工作号 · Pixel 8 发送」，不增加第二个设备选择入口。连接详情始终跟随顶部当前设备；切换设备不清空账号聊天记录。

## 3. 操作始终绑定明确目标

发送、读取、识别账号等操作提交时绑定微信号、设备编号和任务编号。提交后不能因用户切换页面、账号或设备而改变任务目标。

同一设备的手机界面操作排队，跨设备任务可并行。界面展示「排队中 / 执行中」及实际设备；不把所有设备的忙碌状态合并成一个全局加载遮罩。

设备改登其他微信号时，立即标记原关联不可执行并刷新选择器。执行前再次核对账号；不匹配的排队任务停止并提示，不能把旧账号消息发到新账号。

已开始执行的发送遇到断连或结果未知时，不自动换设备重发。诊断展示原目标与结果，先核对手机。切换上下文后，原任务的异常可通过全局任务入口查看，提示里直接写出账号和设备。

## 4. 系统设置扩展

设备列表沿用现有表格结构，增加搜索和组合筛选：搜索别名、编号或微信号；状态「全部 / 可用 / 离线 / 待处理」。数量较少时不显示分页，大量设备时使用分页，显示总数及当前数据范围。

建议列：设备（别名 + 编号）/ 当前微信号（昵称 + 微信号）/ 状态与任务占用 / 连接方式 / 查看。IP 地址收进详情，不增加宽表格列。

设备详情抽屉：当前连接信息、当前登录微信号、可操作性、任务队列、授权管理。设备登录状态异常时展示原因及「重新识别微信号」。配置和管理操作只作用于该设备，标题明确写设备名称。

批量操作仅在勾选设备后出现工具栏，显示选中数量；第一期可规划「重新识别微信号」，逐设备报告成功、失败及跳过。可选中行只在支持批量动作后加入，不预先展示空功能。

撤销授权、删除连接等高影响操作保留单设备处理，后续确有需求再设计批量确认。批量发送、批量控制手机界面与群发是独立能力，不从设备列表的批量选择自动推导。

## 5. AI、转发与诊断的范围

| 页面 | 多设备设计 |
|---|---|
| AI 设置 | 保留全局默认；后续增加账号覆盖时，页面内提供「全局默认 / 指定微信号」范围选择。设备不保存独立 AI 规则，避免同一微信号换设备后回复策略变化。覆盖字段明确显示「继承全局」及恢复继承操作 |
| 会话 AI | 优先级：会话设置 → 账号规则 → 全局规则。自动回复使用账号的设备策略，任务记录实际设备；每条来信最多触发一次回复，跨设备需要去重 |
| 消息转发 | 来源和目标绑定微信号 + 会话。每个目标默认跟随该账号自动选设备，高级项才允许指定设备。离线目标展示执行限制；自动转发跨设备收到同一消息时需要去重，不能产生重复转发 |
| 诊断 | 账号和设备独立筛选；先选账号后设备选项只显示有关设备。每个任务记录明确微信号、实际设备及来源（手动 / AI / 转发）。设备级异常未识别账号时仍可查看 |

同一账号的多设备消息需要服务端合并与去重；UI 展示统一账号时间线，必要时在消息详情展示来源设备，不默认每条消息都加设备标签。

## 6. 全局任务入口

设备数量增加后，右上角在「外观」旁增加紧凑「任务」入口，活动任务存在时显示数量。点击打开轻量任务抽屉，展示账号、设备、操作和状态；点击异常可跳转诊断并带入筛选条件。

无活动任务时入口保持低强调，不常驻多张运行统计卡。不为正常后台进度连续弹提示；失败和需要用户核对的任务提供一次明确反馈。

## 7. 状态与验收

- 两个微信号可以在不同设备上同时执行任务，各自显示进度。
- 同一微信号切换执行设备，历史与草稿保持一致；同一设备切换微信号，历史不能混入。
- 手动指定设备不可用时阻止操作；自动选择展示最终设备。
- 用户提交后切换账号，不改变原任务的账号与设备。
- 设备在线但账号不匹配、权限不足或手机界面不可操作时，不显示为可用。
- 多设备读取相同消息、AI 回复和自动转发不会重复入库或重复发出。
- 批量操作明确选中范围并逐设备显示结果，不只返回一个笼统成功提示。

## 8. 分阶段实施

第一阶段：建立账号与设备独立的数据和任务模型，完成多设备列表、状态、详情、诊断筛选，消息台展示实际执行设备。

第二阶段：提供自动/指定设备策略、跨设备并行与单设备队列、统一消息去重、全局任务抽屉。

第三阶段：按需加入批量设备操作及账号级 AI 覆盖。批量发送、远程手机画面与任意界面操作需另行设计，本方案不把这些功能混入日常消息台。
